# Mac移管と週次更新の契約

## 仕様と現状

2026-11-13の移管元は、11月6日更新済みの838行である。ルートの公開5ファイルは移管元とバイト単位で一致した。古い828行版は使わない。GitHub Pagesはmainのルートを公開し、`build.py`はHTMLだけを生成する。

`pipeline/`に採用済みの元データとmergeを置き、公開JSONを初期入力として別の作業ディレクトリで再構築する。mergeの順序は `collab → buffet → miniature → baby → batch2 → rain → build → csv`。採用判断はClaudeの収集成果物を正とし、収集ファイル欠落・有効追加30件未満では、公開データの変更とpushを止める。

旧テストは期待件数ファイル、固定の名前・件数、古いパスに依存していた。新テストはルートの`spots.json`から期待する行集合を求める。会期の期待値は画面の関数を呼ばず独立に計算する。日付はJSTで固定し、標準は更新日、将来は2026-12-07（以後の週では更新日の翌月7日）とする。

## 不変条件

- `BASELINE`：移管だけでは838行の内容・テンプレート・公開HTMLを変えない。
- `REBUILD`：全mergeの後も行集合と全フィールドを保ち、同じ入力で再実行すると同じ出力になる。
- `SYNC`：JSON、CSV、HTML埋め込みJSONが全行・全フィールドで一致する。
- `UI`：タブ、日時の排他、雨と親子の併用、検索、エリア、地図、お気に入りの保存、ランダム、共有、終了非表示、横スクロール、固定ヘッダーを保つ。JSエラーと外部リクエストは0件。
- `INPUT`：追加の必須フィールド・型・公式URL重複を機械検査する。削除は確定済み期間イベントのみとし、常設・開業日だけの行を保つ。
- `PUBLISH`：有効な新規名30件以上と全検査成功を公開条件にする。定期実行では別セッションのレビューも公開前に行う。

## 検証方法と保証範囲

保存された有限データは全列挙し、再構築前後の集合、連続2回の出力、CSV・HTMLとの対応を比較する。会期の代表・境界・不正形式、フィルタの組合せを列挙し、画面の実装と照合する。JSON/HTML不一致や終了判定・排他を壊した変種を検出できることを確認する。公式情報の将来の変化、予約・購入・空席、任意のブラウザ・無制限の操作列は保証しない。
